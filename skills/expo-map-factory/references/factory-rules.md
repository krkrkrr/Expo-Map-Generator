# 自律で進めるための規則

会場マップ・ファクトリーを、利用者に質問せずに最後まで進めるための規則である。
**他のスキルを読まなくても、ここだけで足りる。**

---

## 1. 絶対規則

1. **利用者に質問しない。** 聞いてよいのは何もない。決まっていないことは 3 章の推測合議で補う。
2. **書いた者は採点しない。** 推測合議の裁定役、位置の抜き取り検査役、verifier は、作業役とは別のサブエージェントで動かす。作業役の説明や結論は渡さない。
3. **テストは実装より先に固定する。** `.feature` とプロパティテストは、コミットした時点で **変更禁止、追加だけ可**。
4. **完了は申告ではなくゲートで決める。** すべての `FACTORY_GATES` 行が `status=GREEN` で、verifier が `accepted` を返したときだけ完了とする。
5. **すべての仕様に出どころを付ける。** 出どころの無い仕様は削る（2 章）。
6. **ブランチはローカルに留める。** マージ、push、公開、アップロードはしない。

## 2. 出どころ

仕様、シナリオ、データの判断の各行に `source` を付ける。

| 値 | 意味 |
|---|---|
| `input:<文番号>` | 利用者の入力の文（`intake.md` の番号） |
| `skill-fixed` | SKILL.md の「固定の前提」 |
| `catalog:GM-xx` | `good-map.md` のカタログ |
| `catalog:IR-xx` | 4 章の暗黙要件カタログ |
| `contract` | `data-contract.md` |
| `inference:<推測の番号>` | 3 章の推測合議で決めた。**最終報告の「代わりに決めたこと」に必ず載せる** |

**出どころの無い機能は足さない。** 推測合議は「決めないと進めない判断」を埋めるためのもので、機能を増やすためのものではない。`good-map.md` の「やらないこと」に当たる機能は、推測でも足さない。

## 3. 推測合議（憲章に書かれていないことを補う）

憲章（`.factory/charter.md`）、固定の前提、GM カタログ、IR カタログ、データの契約のどれにも答えが無い判断が要るときは、**止まらずに、複数のエージェントで推測して決める。**

例: 区画の色の割り当て、検索の 0 件時の文言、出展説明が英語しか無い会社の扱い、ジャンル名の付け方、2 つのホールが 1 ページに描かれた会場図のタブの分け方。

### 手順

1. **問いを書く。** 作業役が `doc/increments/<日付>-<slug>/factory/inferences/NNNN-<slug>.md` に、問い、今わかっている事実、取りうる選択肢（2〜4 個）、それぞれを選んだら何が変わるかを書く。作業役の好みは書かない
2. **独立に推測させる。** 次の 2 役を、互いの答えを見せずに別のサブエージェントで動かす。各役は選択肢を 1 つ選び、理由を 2〜3 行で返す。選択肢に無い案を出してもよい
   - **利用者の代弁**: 非エンジニアが、これから回る展示会のために、自分のスマホで HTML を開いて使う。この人がいちばん迷わないのはどれか
   - **安全と検証の役**: どれが間違ったときに取り消しやすく、テストで確かめられ、主催者の図や情報を歪めないか
3. **裁定する。** 合議に加わっていない 3 つ目のサブエージェントが決める。
   - 2 役が一致したら、それを採る
   - 割れたら、次の順で決める（多数決は使わない。同じ入力なら同じ結論になるようにする）: **安全** → **入力と固定の前提の字義に反しない** → **取り消しやすい** → **単純**
   - 裁定役は、採らなかった案と少数意見を消さずに残す
4. **記録して進む。** 同じファイルに、各役の答え、裁定、`confidence: high | medium | low` を追記する。以降の仕様にはこの判断を `source: inference:NNNN` で付ける
5. **報告する。** すべての推測を最終報告の「あなたの代わりに決めたこと」に 1 行ずつ載せる。`confidence: low` のもの、または 2 役が割れたもののうち重大な順に 3 つまでを「自信のない判断」に載せる

同じ種類の問いが何度も出るなら、最初の裁定を規則として `inferences/` に書き、2 回目からはそれを引く。

### 推測で決めてはいけないもの

次は推測で越えない。

- 憲章の `PROTECTED` に触れること（公開、アップロード、ログインが要るページからの取得）→ 停止条件（6 章）
- 固定済みのテストを変えること → 停止条件（6 章）
- 利用規約が取得を禁じている、または規約の判断がつかないサイトから取得すること → 止まらずに **取らない側に倒し**、会場図の文字だけで作る（SKILL.md 2c）。推測ではなく規則である

## 4. 暗黙要件カタログ（IR）

誰も口にしないが、全員が期待していること。当てはまるものはすべてシナリオとテストにする（`catalog:IR-xx` タグ）。

| ID | 要件 |
|---|---|
| IR-01 | どの操作でも落ちない。未処理の例外とコンソールエラーが 0 |
| IR-02 | 保存したデータが消えない。再読み込みやブラウザの再起動の後も残る |
| IR-03 | 連打、二重の読み込みで重複しない（冪等） |
| IR-04 | 空の状態に案内がある。検索 0 件、お気に入り 0 件、初回起動 |
| IR-05 | 長い入力、空白だけ、絵文字、日本語入力（IME 変換中の Enter）で壊れない |
| IR-06 | 不正な入力（壊れた JSON の読み込みなど）は、理由が分かる日本語で拒否される |
| IR-07 | 全消去などの壊す操作には確認がある |
| IR-08 | 戻る、再読み込み、別タブで状態が矛盾しない |
| IR-09 | 出展者が多くても（例: 2,000 社）実用的な速度で動く |
| IR-10 | 全角と半角の数字、記号が正しく扱われる |
| IR-11 | キーボードだけで主要な操作ができる。コントラストが足りている |
| IR-12 | 外部へ何も送らない。印とメモは端末の外に出ない |

## 5. ゲートの出力

ゲートのスクリプトは、最後の行を必ず次の形で出す。**必須の検査が実行できなかったときは GREEN にしない。**

```
FACTORY_GATES: level=<名前> status=<GREEN|RED|MISCONFIGURED> passed=<n> failed=<n> failing=<名前> skipped=<名前> misconfigured=<名前>
```

### verifier

作業役とは別のサブエージェントに、差分を最初から読ませる。作業役の説明は渡さない。

1. ゲートを自分で実行し、`FACTORY_GATES` の行を自分で得る
2. prove-test（`app-build.md` の 5 章）を自分で実行する
3. 固定済みのテストが変更されていないかを確かめる。**変更されていたら却下**
4. `PROTECTED` に触れていないか、`good-map.md` の「やらないこと」を足していないかを確かめる
5. スライスの完了条件を、書かれた文字どおりに確かめる

```
verdict: accepted | rejected
gates: <自分で得た FACTORY_GATES の行>
test_proves_fix: yes | no | could-not-determine (<理由>)
frozen_tests_modified: yes (<ファイル>) | no
scope: within | exceeded (<何が余分か>)
done_when_met: yes | no (<何がまだ偽か>)
must_fix: <番号付きの一覧、または none>
```

**迷ったら却下する。** 却下の損は実装の 1 往復ぶんにすぎない。

## 6. 停止条件

次のどれかに当たったときだけ止まる。`doc/questions/open/` に問いを置き（`unresolved-questions` の書式）、7 章の書式で途中報告する。

- 同じスライスでゲートが 2 回続けて RED
- `MISCONFIGURED` が出て、`setup_check.py --install` でも直らない（必須の検査が実行できない）
- `PROTECTED` に触れる必要が出た
- 固定済みのテストを変えないと先に進めない
- 位置の抜き取り検査が 2 回続けて不合格

**憲章に書かれていない判断は、停止条件ではない。** 3 章の推測合議で決めて進む。止まった項目を、黙って進行中のまま残さない。

## 7. ステータスファイルと最終報告

### ステータスファイル

`doc/increments/<日付>-<slug>/factory/status.md`。中断から再開するための唯一の拠り所である。

```
increment: <日付>-<slug>
stage: 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | stopped
app_step: <app-build.md の手順番号、アプリを作らないなら ->
slice: <現在 / 全体>
inferences: <件数>（low: <件数>）
last_gates: <FACTORY_GATES の行>
last_verdict: <verifier の verdict>
stop_reason: <停止していれば理由>
```

実行ごとの記録は `factory/runs/<UTC 時刻>-<ステージ>.md` に 1 ファイルずつ書く。

### 最終報告

利用者向け。**技術用語を使わない。** `doc/increments/<日付>-<slug>/factory/report.md` に保存し、本文を利用者に渡す。

```markdown
# <イベント名> の会場マップができました

## 開き方
<「このファイルをスマホに送って開く」の水準で>

## できること
<.feature の正常系シナリオを、1 行 1 項目の平易な文で>

## 地図に載せた数
<SKILL.md ステージ 7 の書式>

## あなたの代わりに決めたこと
<source: inference の全件と、ジャンルの選び方。「〜の場合は〜にしました。違えば教えてください」の形で>

## 自信のない判断（3 つまで）
<選択肢と、それぞれを選んだら何が変わるか>

## やらなかったこと
<意図的に範囲外にしたこと>

## 確かめたこと
<平易な要約。末尾に FACTORY_GATES の行と verifier の verdict をそのまま貼る>

## 次に直したいところがあれば
<この報告への返事が、そのまま次の 1 回の入力になる、と案内する>
```
