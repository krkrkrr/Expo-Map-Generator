# 「良い感じのマップ」の中身

利用者が「良い感じのマップを作って」と言ったとき、それが何を指すかの定義である。
過去に手作業で作り、展示会の当日に実際に使って役に立った会場マップから書き起こした。
元のファイルは factory に同梱しない。**ここに書いた性質だけが基準になる。** 見た目や構造を真似る必要はない。

各項目の ID（GM-xx）は、仕様合議で `source: catalog:GM-xx` として使う。
oneshot-factory の暗黙要件カタログ（IR-xx）と同じ扱いで、当てはまる項目はシナリオとテストにする。

---

## 誰が、いつ使うか（前提にする場面）

- **前日まで**: 机で出展者を眺め、行きたいブースに印を付け、回る順を考える
- **当日**: 片手のスマホで、人混みの中で、今いる場所の近くの印を付けたブースを探す。電波が弱いこともある
- **後日**: 回ったブースのメモを持ち帰り、報告や共有に使う

この 3 つの場面のどれかで役に立たない機能は、入れない。

## 必須（`personal` でも満たす）

### 地図

| ID | 性質 | 確かめ方 |
|---|---|---|
| GM-01 | 主催者の会場図そのものが背景にあり、全ページ（ホール、フロア）をタブで切り替えられる。図を描き直さない | smoke S4 |
| GM-02 | ドラッグで移動、ホイールとピンチで拡大縮小、全体表示ボタンがある。拡大しても文字が潰れない解像度の画像を使う | シナリオ + 目視 |
| GM-03 | 出展者の区画をタップすると、その区画の詳細が開く。共同出展で 1 区画に複数社あれば全社を並べる | smoke S8、シナリオ |
| GM-04 | 区画の色や枠で状態が分かる: お気に入り、訪問済み、検索のヒット、選択中。凡例がある | シナリオ |
| GM-05 | 出展者リスト外のまとまり（ゾーン、パビリオン）は、エリアとして選べ、中の出展者の一覧が出る | シナリオ（ゾーンがある場合） |

### 探す

| ID | 性質 | 確かめ方 |
|---|---|---|
| GM-06 | 社名、ブース番号、キーワードで検索できる。全角と半角、大文字と小文字、カタカナの表記ゆれで取りこぼさない（NFKC で正規化）。空白区切りは AND | smoke S5、PBT |
| GM-07 | 一覧から選ぶと、地図がその区画まで移動し、拡大し、目立たせ、詳細を開く | smoke S5 |
| GM-08 | 部門（カテゴリ）、ホールで絞り込める。ブース順、名前順で並べ替えられる | シナリオ |
| GM-09 | 一覧の各行に、社名、ブース番号、ホール、部門の色が見える | シナリオ |

### 印を付ける、持ち帰る

| ID | 性質 | 確かめ方 |
|---|---|---|
| GM-10 | お気に入り（★）と訪問済み（✓）を、一覧からも詳細からも 1 タップで切り替えられる。「お気に入りのみ」「未訪問のみ」で絞り込める | シナリオ |
| GM-11 | 出展者ごとのメモを書ける。入力が止まったら自動で保存し、保存した時刻を出す | シナリオ |
| GM-12 | お気に入り、訪問済み、メモ、絞り込みの設定が、再読み込みしても、ブラウザを閉じても残る（端末内に保存。外部へ送らない） | smoke S6 |
| GM-13 | お気に入りを、訪問済みの印とメモ付きのテキストでコピーできる（チャットに貼る用） | シナリオ |
| GM-14 | 印とメモを JSON ファイルに書き出し、読み込める。読み込みは既存と統合し、上書きしない。スマホでは共有シートで渡せる | シナリオ |
| GM-15 | 全消去には確認がある。メモの消去は別に確認する | シナリオ |

### 当日の現場で使える

| ID | 性質 | 確かめ方 |
|---|---|---|
| GM-16 | HTML 1 ファイルで完結する。会場図の画像も埋め込む。電波が無くても地図、検索、印付けが動く（ロゴ画像など外部の飾りだけは欠けてよい） | smoke S7 |
| GM-17 | スマホ幅（390px）で横にはみ出さない。一覧は下から出るシートにして、地図を広く使う | smoke S8 |
| GM-18 | ファイルをダブルクリックで開いて（`file://`）動く。サーバーを要しない | smoke（file:// で開く） |

### 正直さ

| ID | 性質 | 確かめ方 |
|---|---|---|
| GM-19 | 位置を推定で補ったもの（番号の無い隣接区画、引き出し線の先など）には「推定」の印がある。詳細にその理由が出る | check_data D5、シナリオ |
| GM-20 | 位置が分からない出展者も一覧から消さない。「マップ位置なし」と出し、選んだら理由を出す | check_data D7、シナリオ |
| GM-21 | データの出どころ（会場図 PDF、出展者リストの URL）と取得日がどこかに出ている | check_data D1、シナリオ |
| GM-22 | 公式の出展者詳細ページがあれば、詳細からリンクする | シナリオ |

## 利用者が関心を答えたとき（入口で「注目ジャンル」を選んだ場合）

| ID | 性質 | 確かめ方 |
|---|---|---|
| GM-23 | 関心のジャンル（2〜5 個）をチップで切り替えられる。複数を選べる | シナリオ |
| GM-24 | 出展者ごとに、ジャンル別の優先度 S/A/B/C がある。地図の枠の色と一覧の印で見分けられ、優先度順に並べ替えられる | シナリオ |
| GM-25 | 対象外の区画をグレーにする、一覧も対象だけにする、優先度の下限（S のみ、A 以上など）を選べる | シナリオ |
| GM-26 | 優先度には、なぜそうしたかの一言と根拠（出展説明の該当箇所、製品名、対応規格などのタグ）が付き、詳細で読める | check_data D9 |
| GM-27 | 根拠が「カテゴリに登録されているだけ」のものは C にとどめ、そう書く。推測で上げない | 合議（ドメインの専門家役） |

## 任意（入口で「当日、現在地を出したい」を選んだ場合）

| ID | 性質 | 確かめ方 |
|---|---|---|
| GM-28 | GPS で現在地を精度の円付きで出す。地図の外なら「マップ外」と出す | シナリオ（位置情報を偽装） |
| GM-29 | 屋内は GPS がずれるので、「今いる場所を地図でタップ」して補正でき、補正は保存され、解除できる | シナリオ |
| GM-30 | 緯度経度と会場図の対応は、公開の地図データ（OpenStreetMap の建物形状など）と会場図の外壁の角を 3 点以上で合わせて求め、出どころを記録する | ADR（Proposed） |

GPS は HTTPS でないと動かないブラウザがある。`file://` で開いたときはその旨を出す。

---

## やらないこと（「良い感じ」に含めない）

- 会場図を独自の図形で描き直すこと（GM-01 に反し、誤りの元になる）
- ログイン、アカウント、サーバーへの保存、アクセス解析
- 経路案内（最短経路の計算）。会場の通路データが無く、正しさを確かめられない
- 地図や出展者情報の Web への公開。主催者の著作物を含むため、配るかどうかは人が決める（憲章の `PROTECTED`）
